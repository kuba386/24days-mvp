# CLAUDE.md

Telegram Mini App «24 DAYS»: 24-дневные курсы по книгам. «Продуктивный год» (Крис Бейли, «Мой продуктивный год») «Атомные привычки» (Джеймс Клир) и «Дела в порядке» (Дэвид Аллен, «Как привести дела в порядок»). UI и тексты на русском.

## Команды

- `npm run dev`: Vite dev server на порту 5173 (конфиг `24days-dev` в `.claude/launch.json`)
- `npm run build`: `tsc -b && vite build`, это же проверка типов (фронт и `api/`)
- `npm test`: vitest, тесты в `tests/` на чистую логику — даты и цепочки, автозамеры и структура курсов, проверка подписи Telegram. Менял `src/dates.ts`, `src/courses.ts`, JSON курсов или `api/_lib/telegram.ts` — запусти. Линтера нет

## Архитектура

- **Фронтенд**: React 18 + Vite + TypeScript, без UI-библиотек. Стили в `src/index.css`, цвета из Telegram `themeParams` (`--tg-theme-*`) с фолбэками для тёмной и светлой темы.
- **Контраст и касания**: для мелкого текста бери `--hint`, `--link` и `--block-text` (цвета темы, подмешанные к `--text`), а не сырые `--block` или `--tg-theme-*`: иначе контраст ниже 4.5. Интерактивные элементы — от 38 px в высоту; ссылки (`.link-btn`) расширяют зону касания паддингом. Белый текст на зелёной заливке — только на `--success-fill`, зелёный текст — `--success-text`: сырой `--success` не дотягивает до 4.5. Проверять на ширине 320 px в светлой и тёмной теме.
- **Навигация**: дополнительные экраны (Мои дела, Статистика, Мои привычки, смена курса или фокуса) — это состояния в `App.tsx`, а не маршруты. `useBackNav` даёт им запись в истории и кнопку «Назад» Telegram (`BackButton`, от версии 6.1), иначе системная «Назад» закрывает всё приложение. Новый такой экран добавляй в условие `useBackNav` и в `closeScreens`.
- **Скилл ui-ux-pro-max** лежит в `.claude/skills/ui-ux-pro-max` (локально, исключён из git). Его общий `--design-system` для нас не подходит (мини-апп берёт цвета из темы Telegram), полезны точечные запросы `search.py "<запрос>" --domain ux`. Запускать по полному пути: `python3 .claude/skills/ui-ux-pro-max/scripts/search.py ...`.
- **Курсы**: `src/courses.ts` (`COURSES`), контент в `src/data/days.json` (year) `src/data/habits.json` (habits) и `src/data/gtd.json` (gtd). 24 дня, 4 блока по 6, дни 6/12/18/24 обзорные, опциональный `metric`. У year свои `actions` на каждый фокус (`product|study|health`). У habits и gtd одно `action` и `examples` по фокусу; у habits в текстах плейсхолдер `{привычка}` (подставляет `fillHabit`). Привычка собирается конструктором как «Что Сколько Когда» с заглавной буквы, поэтому `{привычка}` ставим в «кавычки» или после двоеточия, не после глагола. Опциональный `metric.auto` (`repeats|chain|misses7`) делает замер вычисляемым из `habit_log` (`autoMetricValue` в `src/courses.ts`): пока день открыт, значение пишется в день, после выполнения замирает. Опциональный `picker` у дня (варианты с советами, выбор хранится в `picks` дня) — например, причины прокрастинации в дне 19 year. Опциональный `template` у дня: заготовка заметки для кнопки «Заполнить по шаблону», `…` отмечает места для ввода. Новый курс: JSON, запись в `COURSES`, цвета блоков в `src/blocks.ts`, id в `api/_lib/courses.ts`, `COURSE_DAYS` в `api/remind.ts` и в check-констрейнтах миграции.
- **Прогресс**: `src/hooks/useCloudStorage.ts`, Telegram CloudStorage (лимит 4096 символов на значение). Ключи `course`, `focus`, `habit`, `habit_log` (JSON-массив дат ежедневной отметки привычки, до 300 шт.) и `<keyPrefix>day_N`. Сброс курса пишет в ключи дней пустую строку: при загрузке она читается как «день не начат». У year префикс пустой ради совместимости со старым прогрессом; нет `course`, но есть `focus`, значит пользователь на year. Вне Telegram SDK бросает `WebAppMethodUnsupported`, поэтому стоит try/catch с фолбэком на localStorage.
- **Мои дела (GTD)**: `src/hooks/useTasks.ts`, одна задача на ключ `t_<id>` в CloudStorage (перечисление через `getKeys`), сделанные чистятся через 30 дней. Шаги несут метки `context`/`minutes`/`energy` и `projectId`; вкладка «Сейчас» фильтрует шаги по месту, времени и силам, «Проекты» показывают свои шаги и проекты без шага, «Обзор» — чек-лист недели (`src/hooks/useReview.ts`, ключ `gtd_review`). Сообщения боту без команды пишутся в `days24_inbox`; приложение при открытии забирает их (`GET /api/inbox`) с id `b<id>` и подтверждает удалением (`DELETE /api/inbox?ids=`). Замеры GTD с `metric.auto` считаются из списков, а если списки пустые, вводятся вручную.
- **Инструменты дня** (`src/hooks/useDaily.ts`, общий `src/storage.ts`): «Три главных на сегодня» (`top3`, история `top3_hist` за 60 дней) и энергия (`energy_log`, строки `YYYY-MM-DD H v`, до 200 шт.) — показываются в курсе year. Карта привычек дня 2 habits хранится в `items` дня (`scorecard: true`). Радар блоков (`BlockRadar`) — на обзорных днях.
- **Мои привычки** (`HabitsView`, `src/hooks/useHabits.ts`): произвольное число привычек (до 12) с ежедневными галочками, как в трекерах. Одна привычка — один ключ `hb_<id>` с `{id, name, createdAt, log[]}` (до 280 дат на ключ). Не зависит от курсов; цепочка считается через `softChain`. id генерируем вне функции обновления состояния: React вызывает её дважды, а запись в хранилище должна быть одна.
- **Статистика** (`StatsView`, ссылка «статистика» в шапке): календарь привычки на 6 недель, цепочка сейчас и лучшая (`bestSoftChain`), голоса, выполнение за 30 дней, лучший и худший день недели; прогресс по всем курсам; точки «Трёх главных» за 14 дней; энергия и дела за неделю. Считается только из CloudStorage, без сервера.
- **Кроны**: `api/remind.ts` ежедневно, `api/weekly.ts` по воскресеньям 15:00 UTC (обзор недели, текст под курс).
- **Цепочка привычки** (`softChain` в `src/dates.ts`): правило «не пропускать дважды», одиночный пропуск её не рвёт, два подряд рвут.
- **Правила дней** (`src/App.tsx`): открывается один день в календарные сутки. Следующий день доступен, если предыдущий выполнен и `doneAt !== todayKey()`. Даты локальные `YYYY-MM-DD` (`src/dates.ts`).
- **Бэкенд**: Vercel functions в `api/` (Web `Request`/`Response`, ESM). Относительные импорты обязательно с `.js`, JSON через `with { type: 'json' }`, иначе на Vercel `FUNCTION_INVOCATION_FAILED`.
  - Авторизация: заголовок `Authorization: tma <initData>`, HMAC проверяется в `api/_lib/telegram.ts`
  - БД: Supabase REST с service role (`api/_lib/db.ts`). Схема в `supabase/migrations/`. Таблицы `days24_users`, `days24_posts` (уникальность по `telegram_id, course, day`), `days24_reactions` с RLS без политик, доступ только с сервера
  - `api/telegram.ts`: вебхук бота (/start, /stop), проверяет `x-telegram-bot-api-secret-token`
  - `api/remind.ts`: ежедневный cron (`vercel.json`, `0 4 * * *`), `Bearer CRON_SECRET`
  - Переменные окружения описаны в `.env.example`
- Тред дня (`DayThread.tsx`) скрыт вне Telegram, когда `initData` пустой.

## Настройки Claude Code в репозитории

- `.claude/settings.json`: разрешены тесты, сборка, dev-сервер и чтение git; чтение `.env*` и `.vercel/` запрещено; `git push` всегда со спросом. Хук `PostToolUse` (`.claude/hooks/test-on-change.mjs`) после правки `src/dates.ts`, `src/courses.ts`, `src/data/*.json`, `api/_lib/telegram.ts` или тестов запускает vitest и возвращает упавшие проверки.
- Команды проекта: `/ship` (тесты, сборка, коммит, пуш, ожидание деплоя), `/ux-audit` (контраст, касания, подписи на 320 px в обеих темах), `/new-course` (контент и регистрация нового курса).

## Деплой

- Git remote называется `24` (не `origin`). Пушим прямо в `main`: `git push 24 HEAD:main`, спросив пользователя перед пушем.
- Vercel-проект `24days-mvp` (scope `kuban1`) автодеплоится из `main`, прод: https://24days-mvp.vercel.app
- Supabase: переезд в отдельный проект (в общем `logocrm` таблицы пропали). Новый проект поднимается миграцией `supabase/migrations/0001_init.sql`.
