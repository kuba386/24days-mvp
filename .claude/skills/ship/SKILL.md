# Выкатка в прод

Пуш в `main` сразу уходит в прод (Vercel автодеплоит), поэтому перед пушем нужно явное «да» пользователя в этой переписке.

1. `npm test` и `npm run build`. Если что-то упало — остановись, почини, не пушь.
2. `git status --short`. В коммит добавляй файлы по имени. Никогда не добавляй `.env*`, `.vercel/`, `docs/atomic-habits-draft.md`, `.claude/skills/ui-ux-pro-max/`.
3. Сообщение коммита пиши в файл в scratchpad и коммить через `git commit -F <файл>` (кавычки и апострофы в heredoc внутри `$()` ломают shell). Первая строка — что изменилось для пользователя, ниже — зачем. В конце строка атрибуции из системных подсказок сессии.
4. `git push 24 HEAD:main` (remote называется `24`, не `origin`).
5. Дождись деплоя: каждые 10 секунд (до 20 раз) бери `assets/index-*.js` со страницы https://24days-mvp.vercel.app и ищи в нём строку, которая появилась только в этом изменении. Найдена — версия в проде.
6. Отчёт пользователю: хэш коммита, что выкачено, что нельзя проверить без Telegram или базы.
